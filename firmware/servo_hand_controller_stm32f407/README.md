# STM32 五路位置舵机 + 一路连续舵机控制说明

当前固件版本：`2026-10-29-r36`

> 这是仓库中的关键代码版本。仓库只保留正式机械手控制的应用层、通信层、舵机控制层和板级初始化代码，不包含 STM32 标准外设库、CMSIS、Keil 工程、编译产物、测试工程及旧版本主程序。

## 文件组织

| 目录或文件 | 作用 |
| --- | --- |
| `USER/main.c` | 硬件初始化和主循环 |
| `USER/app_config.h` | 波特率、舵机通道、缓动、WiFi 和演示参数 |
| `USER/stm32f4xx_it.c` | Cortex-M4 异常和中断入口 |
| `USER/system_stm32f4xx.c` | STM32F407 系统时钟与板级初始化 |
| `SYSTEM/command.c` | 三路输入的文本命令解析 |
| `SYSTEM/servo_control.c` | 位置舵机、连续舵机和演示动作 |
| `SYSTEM/comm.c` | 串口、蓝牙和 WiFi 接收缓冲区 |
| `SYSTEM/wifi.c` | ESP8266 入网、TCP 连接和透明传输状态机 |
| `SYSTEM/pca9685.c` | PCA9685 软件 I²C 和 PWM 输出 |
| `SYSTEM/usart.c` | USART1、USART2、USART3 初始化和中断 |
| `SYSTEM/delay.c` | 毫秒和微秒延时 |

## 控制方式

本项目实际配置为：

- `0～4` 号：180° 位置舵机，保持原工程已经调好的回位角度和安全限位。
- `5` 号：360° 连续旋转舵机，按速度和方向控制。
- `2` 号：当前不转动，继续禁用，不接收任何命令。

`0 90` 表示让 0 号位置舵机转到 90°；`5 90` 表示让 5 号连续舵机停止。两套命令共用一个通道号协议，但数值含义不同。

5 号连续舵机按图中 20 ms 周期脉冲表控制。当前这颗舵机实测停止点在 `1670～1810 us` 内，因此默认停止脉宽已设置为中点 `1740 us`。速度命令的脉宽相对实际停止点计算：

| 速度命令 | 脉宽 | 方向及速度 |
| --- | --- | --- |
| `0` | 1240 us | 顺时针最快 |
| `20` | 1340 us | 顺时针次快 |
| `40` | 1440 us | 顺时针再慢 |
| `60` | 1540 us | 顺时针更慢 |
| `80` | 1640 us | 顺时针最慢 |
| `90` | 1740 us | 停止 |
| `100` | 1840 us | 逆时针最慢 |
| `120` | 1940 us | 逆时针稍快 |
| `140` | 2040 us | 逆时针更快 |
| `160` | 2140 us | 逆时针很快 |
| `180` | 2240 us | 逆时针最快 |

`88～92` 是中位死区，统一按停止处理。位置舵机仍保持原来的缓动逻辑，5 号不参与角度缓动。

也可以直接输入图片中的脉宽值，支持 `500～2500 us`：

```text
5 1000      顺时针最快
5 1640      顺时针最慢
5 1740      停止
5 1840      逆时针最慢
5 2240      逆时针最快
```

上电初始化时，5 号固定输出 `1740 us` 停止脉宽，配置位于 `USER/app_config.h` 的 `APP_SPEED_STOP_DEFAULT_US`。

## 停止点校准

先发送：

```text
5 90
STATUS
```

如果 5 号舵机在 1740 us 仍有轻微蠕动，可以在实测停止区间内试 `1710`、`1720`、`1730`、`1750`、`1760`、`1770`，选择最稳定的停止脉宽：

```text
TRIM:5,1740
STATUS
```

每次调整 `5～10 us`，直到舵机停止。允许范围为 `1000～2200 us`。校准结果只保存在当前运行内存，断电后恢复默认值；永久校准请修改 `USER/app_config.h` 中的 `APP_SPEED_STOP_DEFAULT_US`。

也可以发送自动扫描命令：

```text
CAL5
```

`CAL5` 会从 `1000 us` 开始，每 1 秒增加 `10 us`，一直扫描到 `2000 us`，并返回当前脉宽。观察 5 号舵机，在它刚好停止时记下串口显示的脉宽，然后发送任意其他命令结束扫描，再执行：

```text
TRIM:5,停止脉宽
```

需要更细的中心范围时可执行 `FINE5`，它会从 `1670 us` 扫描到 `1810 us`，每步 `5 us`。

还可以发送：

```text
OFF5
```

该命令会关闭 PCA9685 5 号通道的 PWM 输出。如果关闭 PWM 后舵机仍然持续转动，应检查实际连接的通道、信号线、地线、供电和舵机内部调速电位器；发送 `5 90` 可以重新开启并输出停止脉宽。

## 接线

| 接口 | STM32F407 引脚 | 默认参数 | 用途 |
| --- | --- | --- | --- |
| USART1 | PA9 TX / PA10 RX | 115200 8N1 | 电脑串口 |
| USART2 | PA2 TX / PA3 RX | 9600 8N1 | 蓝牙模块透传 |
| USART3 | PB10 TX / PB11 RX | 115200 8N1 | ESP8266 WiFi |
| 软件 I²C | PB8 SCL / PB9 SDA | 7 位地址 0x40 | PCA9685 |

蓝牙默认波特率已改为常见的 `9600`，配置位于 `USER/app_config.h` 的 `APP_BLUETOOTH_BAUD`。蓝牙模块 TX 接 PA3，RX 接 PA2，并必须与开发板共地。如果模块已经配置为其他波特率，可以从电脑串口发送：

```text
BTBAUD:115200
```

支持 `4800`、`9600`、`19200`、`38400`、`57600`、`115200`、`230400`。这个命令修改的是 STM32 的 USART2 波特率，手机蓝牙串口本身不需要设置波特率，但蓝牙模块内部 UART 波特率必须与之相同。发送 `BT?` 可查询当前设置。

ESP8266 的 TX 接 PB11，RX 接 PB10，模块要使用独立稳定的 3.3 V 电源，并与开发板共地。

## WiFi 使用

当前舵机端 ESP8266 按 AT 固件工作，作为 STA 客户端连接 demo：

- 热点名称：`PYY_8266`
- 热点密码：`12345678`
- TCP 服务器：`192.168.4.1:80`

舵机端 ESP8266 加入该热点后主动连接 demo 的 TCP 服务器，并进入透明传输。

机械手单片机上电或单独复位时，ESP8266 可能仍停在透明模式。固件会先静默发出 `+++` 退出透传、关闭旧连接，再发送 `AT` 重新连接，避免启动阶段的 `AT` 被当作 TCP 数据发到 demo。

正常的 demo 串口不应再持续出现下面这种报文：

```text
[WIFI RX] +IPD,0,4:AT
```

如果仍然出现，应同时复位机械手和两个 ESP8266，再重新上电。

WiFi 接收两类数据：

```text
GLOVE,50,53,65,65,34
DEMO_ONCE
```

`GLOVE` 数据映射为：

```text
S1 -> CH4
S2 -> CH3
S3 -> CH2，忽略
S4 -> CH1
S5 -> CH0
```

CH0、CH4 的机械方向为：`min_angle` 是张开，`max_angle` 是回收。
CH1、CH3 相反：`max_angle` 是张开，`min_angle` 是回收。

| 手套通道 | 舵机通道 | 弯曲百分比方向 |
| --- | --- | --- |
| S1 | CH4 | 0%→min，100%→max |
| S2 | CH3 | 0%→max，100%→min |
| S3 | CH2 | 忽略 |
| S4 | CH1 | 0%→max，100%→min |
| S5 | CH0 | 0%→min，100%→max |

五路全弯到 `70%` 以上时会启动一次完整演示。演示期间机械手继续保存实时手套数据；任意一路降到 `70%` 以下后，会立即取消演示并恢复单指跟随，不需要先发送 `X`。

舵机端串口正常连接时会依次显示：

```text
wifi: joined PYY_8266
wifi: connected to demo TCP server
```

demo 端对应显示：

```text
[WIFI] TCP client connected
```

WiFi 的 AT 初始化、入网、TCP 连接和透明模式全部使用非阻塞状态机，不再在蓝牙命令处理前等待 AT 超时；WiFi 模块异常或未连接时，蓝牙仍可立即发送 `PING`、`STATUS`、`5:90` 等命令。

透明模式增加 2 秒接收看门狗。看门狗只由成功解析的 `GLOVE` 数据刷新，杂散 AT 文本或半截报文不会掩盖链路故障。持续收不到有效手套数据，或 ESP8266 返回 `ready`、`WIFI DISCONNECT` 时，固件会自动退出残留透传并重新完成 `AT`、入网、TCP 连接和透明模式初始化。这样即使舵机动作瞬间干扰导致 ESP8266 单独复位，也不需要手动断电或发送 `WIFIFIX`。

本版同时修正了 `SYSTEM/delay.c` 的固定 `SysTick` 装载值。原值按约 21 MHz 编写，而当前主频为 168 MHz，导致一次 1 ms 延时实际只有约 0.125 ms；这会让 WiFi 超时、舵机缓动和校准节拍整体快约 8 倍。现在改为按 `SystemCoreClock` 动态计算。

demo 在 WiFi 不可用时可以通过 USART1 有线发送同样的控制命令：

```text
demo PA9 TX -> 机械手 PA10 RX
GND 共地
```

`WIFI?` 会返回具体的失败阶段：

```text
wifi: module no response, uart=115200
wifi: module OK, AP join failed, uart=115200
wifi: AP joined, waiting TCP, uart=115200
wifi: TCP connected, uart=115200
```

如果没有 USB-TTL，可以通过蓝牙修改 ESP8266 的 UART 波特率：

```text
WIFIBAUD:9600
WIFIBAUD:115200
```

USART3 接收中断在 WiFi 配置和连接阶段保持开启，收到的字节进入独立 AT 环形缓冲区，避免 115200 波特率下因轮询过慢产生接收溢出和半截应答。

r27 将 ESP8266 AT 响应缓冲区扩大到 512 字节，并忽略手套端经过共用 USART1 链路发送的 `[ADC]`、`[BEND]`、`[WIRED TX]` 等方括号诊断日志，这些日志不会再被误解析成控制命令。

r28 让蓝牙命令优先于高频手套日志处理，并清除串口帧错误、噪声错误和溢出错误。尚未收到任何蓝牙数据时，机械手每 3 秒发送一次 `BT READY 9600, waiting command`；手机能看到这条消息说明单片机到蓝牙模块的 TX 通路正常，看不到则应检查蓝牙模块供电、PA2/PA3 接线和模块 UART 波特率。

r29 在首次收到任何蓝牙字节后回复 `BT RX PATH OK`，用于确认手机到 PA3 的接收通路；`PING` 不再依赖回车或换行，收到完整四个字节就立即返回 `PONG`。

r30 修正了 r26～r29 中 SysTick 装载值被重复除以一百万的问题。此前 `delay_ms(10)` 实际几乎不等待，导致蓝牙低波特率下收到第一个字符就被误判为一条命令，也让 PCA9685 上电等待和舵机回中节拍失效。r30 恢复为正确的 168 MHz 周期数。

r31/r32 新增 WiFi 软硬连接开关。`WIFIOFF` 会先退出透明模式、关闭 TCP、断开 AP，再停止 WiFi 接收和自动重连，蓝牙与 USART1 仍然工作；`WIFION` 会重新执行 ESP8266 初始化并恢复 WiFi。关闭期间 `WIFI?` 返回 `wifi: disabled by WIFIOFF`。

r33 在 `WIFIOFF` 后同时屏蔽所有来源的 `GLOVE` 数据。手套端在 WiFi 断开后会改用 USART1 有线发送 `GLOVE`，如果不屏蔽这些报文，蓝牙设置的舵机仍会立即被有线手套数据覆盖。发送 `WIFION` 后恢复接收 `GLOVE` 并重新连接 WiFi。

r34 新增 `CH5_ONCE`：六号连续舵机按速度命令 `100` 左转 1 秒、速度命令 `80` 右转 2 秒、速度命令 `100` 左转 1 秒，然后停止。该命令由仿生手五路全部达到 100% 时自动发送，只执行一次；任一通道降到 90% 以下后才允许再次触发。若实际左右方向相反，交换 `APP_DEMO_CH5_SPEED_A` 和 `APP_DEMO_CH5_SPEED_B`。

r35 将 `CH5_ONCE` 改为独立的一次性序列。此前仿生手持续发送的普通 `GLOVE` 会因为五路没有全部达到 70% 而调用 `Servo_CancelDemo()`，导致刚启动的六号舵机动作在约 100 ms 内被取消。现在后续 `GLOVE` 只更新位置舵机目标，不会中断 CH5 的四秒动作。

r36 将 S3 触发的 `CH5_ONCE` 缩短为左 300 ms、右 600 ms、左 300 ms，然后停止；原来的 `DEMO5` 循环演示仍保持 1 秒、2 秒、1 秒不变。

## 控制命令

建议每条命令以回车、换行或 `CRLF` 结束。若串口助手没有“发送新行”选项，直接发送后约 20 ms 也会自动识别为一条命令。三个来源可以同时在线，谁发送命令，就由哪个接口返回应答。

| 命令 | 示例 | 功能 |
| --- | --- | --- |
| 位置舵机 | `0 90` | 0 号位置舵机转到 90°，按原安全限位裁剪 |
| 单通道简写 | `90` | 0 号位置舵机转到 90° |
| 连续舵机停止 | `5 90` | 5 号连续舵机停止 |
| 连续舵机正转 | `5 110` | 5 号舵机中速正转 |
| 连续舵机反转 | `5 70` | 5 号舵机低速反转 |
| 原始脉宽控制 | `5 1740` | 5 号直接输出 1740 us，当前舵机停止点 |
| 批量设置 | `0:90,1:30,5:105` | 0、1 号设置角度，5 号设置速度 |
| 全部设置 | `ALL:90` | 0～4 号转到 90°，5 号停止 |
| 保持位置并停车 | `STOP` | 位置舵机保持当前角度，5 号停止 |
| 回到原回位角度 | `HOME` | 0～4 号回原回位角度，5 号停止 |
| 停止点校准 | `TRIM:5,1740` | 只设置 5 号连续舵机的停止脉宽 |
| 粗扫停止点 | `CAL5` | 1000～2000 us 自动扫描并显示当前脉宽 |
| 细扫停止点 | `FINE5` | 1670～1810 us、每步 5 us 扫描 |
| 关闭 CH5 输出 | `OFF5` | 关闭 PCA9685 5 号通道 PWM，用于硬件排查 |
| 状态 | `STATUS` | 返回舵机角度、手套累计包数、最后数据来源和演示状态 |
| 模拟动作 | `D` | 演示 0、1、3、4 号手指，随后执行 5 号连续舵机组合动作 |
| 五路手套数据 | `GLOVE,0,50,20,80,100` | 按百分比控制 CH0、CH1、CH3、CH4，S3/CH2 忽略 |
| 一次性模拟 | `DEMO_ONCE` | 完整执行一遍手指和CH5演示后自动停止并恢复传感器控制 |
| 单独测试 CH5 | `DEMO5` | 立即执行 100/1秒 → 80/2秒 → 100/1秒 → 停止 |
| S3触发 CH5 | `CH5_ONCE` | 左300ms → 右600ms → 左300ms → 停止，只执行一次 |
| 停止演示 | `X` | 停止演示，位置保持，5 号停止 |
| 通信测试 | `PING` | 返回 `PONG` |
| WiFi 状态 | `WIFI?` | 返回模块和 TCP 客户端状态 |
| 关闭 WiFi | `WIFIOFF` | 暂停 WiFi 接收和自动重连，保留蓝牙/串口 |
| 恢复 WiFi | `WIFION` | 重新初始化并连接 WiFi |
| WiFi 恢复 | `WIFIFIX` | 退出残留透传、关闭旧 TCP 并重新连接 |
| 蓝牙波特率 | `BTBAUD:9600` | 从电脑串口修改蓝牙串口波特率 |
| 查询蓝牙波特率 | `BT?` | 返回当前蓝牙串口波特率 |
| 蓝牙发送测试 | `BTTEST` | 从单片机向蓝牙模块发送测试文本 |
| WiFi AT测试 | `WIFIAT` | 向ESP8266发送基础`AT`并把应答返回蓝牙 |
| WiFi AT透传 | `WIFIAT:AT+CWMODE?` | 通过蓝牙向ESP8266发送任意AT指令 |

`STATUS` 中新增的一行用于判断实时控制链路：

```text
GLOVE rx count=126 source=wifi demo=stop
```

`source=wifi` 表示最后一条有效数据来自 WiFi；`count` 在弯曲手指时应持续增加；`demo=stop` 表示当前没有被演示状态占用。

如果弯曲手指时串口出现：

```text
wifi: rx timeout, reconnecting
wifi: module reset, full reconnect
```

说明首次动作后链路确实中断，固件已经接管恢复。若每次动作都会出现上述日志，应检查舵机与 ESP8266 是否共用容量不足的 3.3 V 电源，并给 ESP8266 电源脚就近并联 `470～1000 uF` 电容。

`D` 演示顺序：

1. CH0 → CH1 → CH3 → CH4 依次往复运动。
2. CH4 完成回位并停顿后，CH5 以速度命令 `100` 运行 1 秒。
3. CH5 以速度命令 `80` 运行 2 秒。
4. CH5 以速度命令 `100` 运行 1 秒。
5. CH5 停止，然后从 CH0 开始下一轮循环。

手套持续发送数据时，只要任意一路没有达到全弯阈值，新的 `GLOVE` 数据就会退出 `D` 或 `DEMO_ONCE`，以保证实时手指控制优先。

如果只想立即测试 5 号动作，不必等待四路手指完成，直接发送：

```text
DEMO5
```

注意：`ALL:90` 会移动位置舵机，不是“全部停止”。需要保持 0～4 号当前角度并让 5 号停止时，请发送 `STOP`。

## 代码结构

代码按“输入 → 命令 → 舵机 → PCA9685”分层：

```text
USART1 串口 ─┐
USART2 蓝牙 ─┼─> comm.c ─> command.c ─> servo_control.c ─> pca9685.c ─> 舵机
USART3 WiFi ─┘                              │
                                      5号停止点/速度换算
```

- `USER/main.c`：只负责硬件初始化、启动信息和主循环。
- `USER/app_config.h`：集中放置波特率、通道数量、缓动、演示和 5 号舵机参数。
- `SYSTEM/command.c`、`command.h`：解析文本命令并返回状态，不直接操作舵机。
- `SYSTEM/servo_control.c`、`servo_control.h`：保存舵机状态，处理五路位置舵机和 5 号连续舵机。
- `SYSTEM/comm.c`、`comm.h`：三路串口环形接收缓冲区和统一应答。
- `SYSTEM/wifi.c`、`wifi.h`：ESP8266 AP、TCP 服务器和透明传输管理。
- `SYSTEM/pca9685.c`、`pca9685.h`：原工程 PWM 参数和连续舵机微秒级脉宽输出。

日常修改位置：

- 调整 0～4 号回位角度、安全限位或通道启用状态：修改 `SYSTEM/servo_control.c` 顶部数组。
- 调整波特率、主循环周期、缓动速度、演示间隔或 5 号停止点范围：修改 `USER/app_config.h`。
- 修改命令格式或新增命令：修改 `SYSTEM/command.c`。

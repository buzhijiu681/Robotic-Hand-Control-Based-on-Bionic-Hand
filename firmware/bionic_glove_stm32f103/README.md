# STM32F103 手套五路传感器 WiFi 桥接说明

> 这是仓库中的关键代码版本。仓库只保留手套端应用源码和串口驱动，不包含 STM32 标准外设库、CMSIS、Keil 工程及编译产物。

## 文件组织

| 文件 | 作用 |
| --- | --- |
| `main.c` | 五路 ADC、标定/滤波、WiFi 报文和 USART1 有线兜底 |
| `app_config.h` | WiFi、端口、ADC、标定和动作阈值参数 |
| `stm32f10x_conf.h` | 标准外设库配置 |
| `drivers/delay.c` | SysTick 毫秒延时 |
| `drivers/usart1.c` | USB 调试和有线控制串口 |
| `drivers/usart2.c` | ESP8266 AT 指令与 TCP 通信串口 |

## 固件版本

`2026-10-29-r22`

## 串口分配

| 串口 | 引脚 | 连接设备 | 波特率 |
| --- | --- | --- | --- |
| USART1 | PA9 TX / PA10 RX | USB-TTL、手套数据输入 | 115200 |
| USART2 | PA2 TX / PA3 RX | ESP8266 | 115200 |

USART1 和 USART2 使用独立环形接收缓冲区，接收中断不再直接转发字节，避免传感器数据破坏 ESP8266 的 AT 指令。

## 本地五路弯曲传感器接线

当前 demo 的 STM32F103 会直接采集以下五路 ADC，每 500 ms 更新一次。

3D 建模工程中的实际接线为：

```text
3.3V -> 弯曲传感器 -> ADC节点 -> 10kΩ -> GND
                       |
                 PA0/PA1/PA4~PA6
```

| 传感器 | STM32F103 ADC 引脚 |
| --- | --- |
| S1 | PA0 |
| S2 | PA1 |
| S3 | PA4 |
| S4 | PA5 |
| S5 | PA6 |

五路必须各使用一个独立的 10 kΩ 下拉电阻，只能使用 3.3 V，不能接 5 V。PA2/PA3 保留给 USART2（ESP8266）。五路 ADC 的原始值范围是 0～4095。

## WiFi 参数

- ESP8266 模式：AP + TCP 服务器
- 热点：`PYY_8266`
- 密码：`12345678`
- 服务器地址：`192.168.4.1`
- 端口：`80`

参数集中在 `app_config.h`。

## 当前手套数据格式

固件可以识别手部传感器工程当前输出的 RAW 行：

```text
RAW  S1:1234 S2:2345 S3:3456 S4:4567 S5:5678
```

USB-TTL 上会显示：

```text
[USB RX] RAW  S1:1234 S2:2345 S3:3456 S4:4567 S5:5678
[BEND] S1=0% S2=0% S3=0% S4=0% S5=0%
[WIFI TX OK] GLOVE,0,0,0,0,0
```

五路 ADC 会先用三点标定转换为 `0～100%` 弯曲量，再通过 WiFi 发送：

```text
GLOVE,0,0,0,0,0
GLOVE,50,53,65,65,34
GLOVE,100,100,100,100,100
```

当五路都超过 `70%` 时，发送一次：

```text
DEMO_ONCE
```

触发演示后仍会继续发送实时 `GLOVE` 数据。机械手在任意一路松开后立即退出演示，恢复单指实时控制。

五路 ADC 每 10 ms 采样并进行 5 点中值滤波，WiFi 每 100 ms 更新一次，USB 日志每 250 ms 输出一次。`CIPSEND`、等待 `>` 和等待 `SEND OK` 全部改为非阻塞状态机，因此 WiFi 暂时不可用时，ADC 采样、USB 日志和有线兜底仍会继续运行。`[WIFI TX OK]` 表示 ESP8266 已返回 `SEND OK`；出现 `[WIFI TX FAIL]` 时，固件会补发当前有线数据，并在 1 秒后自动执行 `+++`、关闭旧连接、重新配置 AP 和 TCP 服务器。

如果 WiFi 不可用，demo 会自动改从 USART1 有线发送同样的 `GLOVE`/`DEMO_ONCE` 文本。接线：

```text
demo PA9 TX -> 机械手 STM32F407 PA10 RX
demo GND    -> 机械手 GND
```

固件也兼容不带 `RAW` 前缀的 `S1:... S2:...` 五路文本。若五路都接近 4095，USB 串口会提示检查每个 10 kΩ 电阻是否可靠接到 GND。

## 测试方法

1. 编译并下载 demo 工程。
2. USB-TTL 使用 115200 8N1 打开串口。
3. 启动信息应显示 `2026-10-29-r22` 和 `ESP8266 TCP server ready`。
4. 舵机端 ESP8266 连接热点 `PYY_8266`，再连接 TCP `192.168.4.1:80`。
5. 连接成功后 USB 调试串口显示 `[WIFI] TCP client connected`。
6. demo 会自动读取 PA0/PA1/PA4/PA5/PA6，USB 端会显示五路值和即将发送到 WiFi 客户端的报文。

如果 ESP8266 上电比 STM32 慢，demo 会每 5 秒自动重试；日志出现 `[ESP] retry WiFi setup` 时不需要再次按复位。

如果弯曲手指后出现 `[WIFI TX FAIL] recovery scheduled`，随后看到 `[ESP] retry WiFi setup`，说明首次链路已异常，固件正在自动恢复；这段时间有线 `GLOVE` 数据仍会继续作用。若每次弯曲舵机时都稳定复现 ESP8266 复位，应优先检查机械手舵机电源与 ESP8266 的 3.3 V 电源是否互相拉低。

如果暂时不接本地传感器，也可以从串口调试工具发送一行 RAW 数据做外部输入转发测试。

如果更换了传感器、重新插拔排线或发现静止时百分比不为 0，请保持五指完全伸直，从 USB 串口发送：

```text
CAL
```

固件会重新采集五路张开基线并输出：

```text
[CAL] open S1=... S2=... S3=... S4=... S5=...
```

上电时也会自动执行一次基线采集，因此正常情况下不需要每次手动发送 `CAL`。

S2 弯曲百分比单独使用 `135%` 增益，同时加入 80 counts 的张开死区，避免静止漂移被识别成弯曲。参数位于 `DEMO_S2_GAIN_PERCENT`、`DEMO_S2_OPEN_DEADBAND` 和 `DEMO_S2_FULL_SCALE_ADC`，可按传感器实际变化范围继续调整。

当 S3 达到 95% 时，会向机械手发送一次 `CH5_ONCE`。机械手六号舵机随后执行：

```text
左运动 300 ms -> 右运动 600 ms -> 左运动 300 ms -> 停止
```

动作保持期间不会重复发送，S3 降到 90% 以下并再次到达 95% 后才允许再次触发。
